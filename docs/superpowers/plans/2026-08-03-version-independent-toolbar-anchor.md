# Codex 版本无关顶部菜单锚点修复计划

> **执行方式：** 用户明确要求当前会话内联执行，不使用子代理。步骤采用复选框跟踪。

**目标：** 让用量组件基于稳定的菜单语义与几何关系显示在顶部菜单右侧，并修正尚未尝试挂载时的误导日志。

**架构：** 注入脚本只接受页面顶部唯一可见的 `role="menubar"`，向上遍历寻找横向、顶部、足够宽的承载容器，再把组件插入菜单分支之后。控制器只有在取得有效展示文本并调用 `update()` 后，才把未挂载解释为锚点缺失。

**技术栈：** Node.js 24、Node 内置测试运行器、CDP Runtime、浏览器 DOM API；零 npm 依赖。

## 全局约束

- 不依赖 Codex 版本号、Help 文案、语言、元素 ID、CSS 类名或固定 DOM 层级。
- 不新增 `/wham/usage` 或重置券请求，不新增独立刷新定时器。
- 找不到唯一可信锚点时保持不显示，不向聊天内容区回退。
- 不修改官方 AppX、`app.asar` 或官方入口。
- 未经用户再次批准，不关闭或重启 Codex。
