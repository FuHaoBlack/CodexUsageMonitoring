# Codex 顶部用量展示设计

- 日期：2026-07-29
- 目标版本：Codex Desktop `26.721.4979.0`（Windows）
- 设计状态：用户已分段确认，待最终审核
- 实施状态：尚未修改或安装

## 1. 背景与目标

在 Codex 桌面端顶部持续展示当前账户的每周剩余用量、每周额度重置时间、剩余用量重置次数，以及能够从 Codex 官方响应中观察到时的最近一次重置到期日。

目标要求：

1. 使用 Codex 自己的刷新结果，不创建额外额度请求，也不设置独立额度刷新定时器。
2. 不修改 `WindowsApps`、Codex 签名文件或 `app.asar`。
3. 宽窗口显示完整文案，窄窗口自动显示缩略文案。
4. 剩余重置次数为 `0` 时，隐藏全部重置次数相关内容。
5. 注入失败不能影响 Codex 正常启动和工作。
6. 采用一次点击入口：辅助程序自动启动 Codex，Codex 退出时辅助程序退出；不设置 Windows 登录自启。

非目标：

1. 不修改 Windows 原生“文件 / 编辑 / 视图 / 帮助”菜单。
2. 不提供点击、刷新、重置额度或打开设置等交互。
3. 不改变 Codex 官方请求频率、React Query 缓存或账户状态。
4. 不显示 5 小时、月度、Spark 或其他额度窗口。

## 2. 当前程序证据

当前安装包位于：

```text
C:\Program Files\WindowsApps\OpenAI.Codex_26.721.4979.0_x64__2p2nqsd0c76g0
```

只读检查确认：

1. Codex Desktop 是 Electron 应用。
2. “帮助”位于 Electron 主进程创建的 Windows 原生菜单中，CDP 只能控制渲染页面，不能安全地向该原生菜单追加实时组件。
3. 官方每周用量查询为 `GET /wham/usage`，React Query 键为 `rate-limit-status`：
   - 前台每分钟刷新；
   - 窗口重新获得焦点时刷新；
   - 后台不继续定时刷新；
   -任务成功提交、账户变化或触发用量上限事件时会使查询失效并重新获取。
4. 官方重置券明细查询为 `GET /wham/rate-limit-reset-credits`，React Query 键为 `rate-limit-reset-credits`：
   - 相关官方界面挂载时每分钟刷新；
   - 成功使用重置券后重新获取；
   - 可用券由 `status === "available"` 判断；
   - 到期时间字段为 `expires_at`。
5. `/wham/usage` 中包含 `rate_limit_reset_credits.available_count`，因此即使未观察到重置券明细，仍可展示剩余次数。

## 3. 方案比较与决策

### 3.1 采用：回环 CDP 运行时注入

本地辅助程序使用仅绑定 `127.0.0.1` 的 Chrome DevTools Protocol 启动官方 Codex，观察 Codex 已经发出的官方响应，并向渲染页面顶部工具栏注入只读组件。

采用理由：

1. 与当前社区 Codex 皮肤和增强项目的主流方式一致。
2. 不破坏签名与 Store 自动更新。
3. 可以同时观察官方网络响应和维护渲染页面组件。
4. 回退只需从原官方入口启动 Codex。

### 3.2 未采用：外部透明覆盖层

优点是完全不进入 Codex 渲染页面；缺点是窗口定位、多屏 DPI、焦点、最大化和置顶行为复杂，视觉上也不是真正属于 Codex 工具栏。

### 3.3 未采用：修改 `app.asar`

能够直接复用内部 React 状态，但每次 Codex 更新都可能覆盖修改，并涉及包完整性、签名和版本差异，维护与恢复风险最高。

## 4. 展示位置与文案

### 4.1 位置

Windows 原生菜单保持不变。组件注入 Codex 渲染页面顶部工具栏右侧，与当前任务标题、模型选择等页面控件处于同一行。

组件没有点击行为，使用普通文字颜色与 Codex 当前主题变量，设置为非交互元素，不夺取键盘焦点。

### 4.2 完整文案

当剩余重置次数大于 `0` 且已观察到最近到期日：

```text
用量：每周 66%（8 月 5 日 12:09 重置）｜剩余重置次数：1（最近一次重置到期：8 月 1 日）
```

当剩余重置次数大于 `0`、但尚未观察到到期日：

```text
用量：每周 66%（8 月 5 日 12:09 重置）｜剩余重置次数：1
```

当剩余重置次数为 `0`：

```text
用量：每周 66%（8 月 5 日 12:09 重置）
```

### 4.3 缩略文案

当剩余重置次数大于 `0`：

```text
周 66%｜↻（1）
```

当剩余重置次数为 `0`：

```text
周 66%
```

### 4.4 完整与缩略切换

不使用固定窗口宽度猜测。注入组件测量自身可用空间：

1. 完整文案能够在工具栏内单行显示时使用完整模式。
2. 完整文案会挤压现有工具栏控件或溢出时切换为缩略模式。
3. 通过 `ResizeObserver` 或等效的容器尺寸观察处理窗口变化。
4. 尺寸观察只切换本地文案，不触发任何额度请求。

## 5. 数据流与字段规则

```text
Codex 官方请求
    ↓
CDP Network 只读观察响应
    ↓
本地辅助程序解析并净化
    ↓
仅发送四类展示值到渲染页面
    ↓
顶部只读组件
```

### 5.1 每周剩余用量

来源：

```text
rate_limit.primary_window
rate_limit.secondary_window
```

规则：

1. 选择 `limit_window_seconds` 为 7 天（允许极小格式误差）的窗口。
2. 没有可确认的 7 天窗口时不显示组件，不拿其他周期冒充“每周”。
3. `used_percent` 必须是有限数值。
4. `remaining_percent = clamp(round(100 - used_percent), 0, 100)`。

### 5.2 每周重置时间

来源：

```text
weekly_window.reset_at
```

规则：

1. `reset_at` 按 Unix 秒解析。
2. 使用 Windows 当前时区。
3. 中文格式为 `M 月 d 日 HH:mm`，分钟保留两位。
4. 字段缺失或时间无效时不显示组件，避免只有百分比而没有本次额度周期边界。

### 5.3 剩余重置次数

首选来源：

```text
/wham/usage
rate_limit_reset_credits.available_count
```

规则：

1. 只接受非负整数。
2. 大于 `0` 时显示次数。
3. 等于 `0` 时隐藏全部重置相关内容。
4. 字段缺失时只显示每周用量，不把未知值当作 `0`。

### 5.4 最近一次重置到期日

来源：

```text
/wham/rate-limit-reset-credits
credits[].status
credits[].expires_at
```

规则：

1. 只考虑 `status === "available"` 的记录。
2. 忽略缺失、无效或已经过期的 `expires_at`。
3. 取未来最早到期时间，作为“最近一次重置到期”。
4. 只显示月、日，不虚构具体时分。
5. 如果 Codex 当前没有自行请求该接口，辅助程序不补发请求；此时显示次数但省略到期日。

## 6. 组件与进程设计

### 6.1 `launcher.mjs`

职责：

1. 通过已安装 AppX 信息定位最新 `Codex.exe`，不写死版本目录。
2. 检查是否已有未启用本方案的 Codex 主进程：
   - 如果有，给出清晰中文提示，请用户先正常关闭；
   - 不强制结束进程。
3. 选择空闲本地端口，并使用以下原则启动 Codex：
   - 调试地址仅为 `127.0.0.1`；
   - 端口只在本次 Codex 生命周期内使用。
4. 连接主渲染目标并启用必要的 CDP `Network`、`Page`、`Runtime` 域。
5. 只处理精确匹配的两个官方 GET 响应路径。
6. 在辅助进程中解析原始响应，页面端只接收净化后的展示快照。
7. 页面重载、执行上下文重建或目标变化后重新注入。
8. 同时监控本次启动的 Codex 主进程与 CDP 浏览器端点：
   - Codex 正常退出、崩溃或被用户结束后，关闭 CDP 连接并在短暂宽限期后退出，目标为两秒内不再保留辅助进程；
   - 仅渲染进程刷新、任务切换或执行上下文重建时不退出，而是重新连接并恢复组件；
   - 只有主进程已经结束且 CDP 端点也不可用时，才判定整次 Codex 会话结束。

实现使用当前本机 Node.js 24，零 npm 依赖。

### 6.2 `inject.js`

职责：

1. 使用可信的页面工具栏锚点定位目标区域。
2. 创建唯一的组件根标记，例如 `data-codex-usage-toolbar`。
3. 渲染完整/缩略文案并跟随当前亮色或暗色主题。
4. 通过 `ResizeObserver` 处理可用宽度变化。
5. 通过 `MutationObserver` 处理 React 重绘或页面导航造成的 DOM 替换。
6. 接收新的净化快照后原位更新。

约束：

1. 不调用 `fetch`、`XMLHttpRequest`、WebSocket 或任何额度接口。
2. 不读取或修改 Codex React 内部状态。
3. 不创建按钮、点击事件或快捷键。
4. 找不到可信锚点时不向其他位置盲目插入。

### 6.3 `start.ps1`

职责：

1. 以隐藏控制台方式启动 `launcher.mjs`。
2. 将启动失败原因转换成清晰中文提示。
3. 不请求管理员权限。

### 6.4 `uninstall.ps1`

职责：

1. 删除新增开始菜单快捷方式。
2. 删除本方案的本地安装目录和日志。
3. 不修改或删除官方 Codex 文件、设置、任务或账户数据。

## 8. 状态与异常处理

### 8.1 首次响应尚未到达

不显示组件，不显示占位百分比或“0%”。

### 8.2 官方刷新偶发失败

保留本次 Codex 启动期间最后一次成功快照，等待 Codex 自己的下一次刷新；辅助程序不补发请求。

### 8.3 退出或切换账户

页面导航、身份状态变化或新响应显示账户发生变化时，立即清除旧快照和组件。新账户官方用量返回前不显示，避免短暂泄露旧账户额度。

账户标识只用于内存中的变化判断，不写入日志或磁盘。

### 8.4 Codex 页面结构更新

如果找不到经过验证的工具栏锚点：

1. 不注入组件；
2. Codex 原界面继续工作；
3. 日志记录“未找到顶部工具栏”及应用版本，不记录页面内容。

### 8.5 官方响应字段更新

字段无法确认时只隐藏对应内容。不得把缺失值解释为 `0`，不得让解析异常传播到 Codex 页面。

### 8.6 Codex 进程结束

正常关闭、崩溃或强制结束 Codex 后，辅助程序停止观察、关闭日志文件并自动退出。渲染页面重载或渲染子进程重建不视为 Codex 退出，避免正常导航时辅助程序被误关。

## 9. 安全与隐私

1. CDP 仅绑定 `127.0.0.1`，不暴露到局域网。
2. 选择本次运行的随机空闲端口，避免固定端口长期暴露。
3. 不保存访问令牌、Cookie、账户 ID、请求头或原始响应正文。
4. 页面只收到：
   - 每周剩余百分比；
   - 每周重置时间；
   - 剩余重置次数；
   - 可选的最近到期日。
5. 日志只记录时间、Codex 版本、连接状态、注入状态和字段缺失类别。
6. 日志按小文件轮转，避免无限增长。
7. 所有异常采用 fail-open：最多不显示组件，不能阻断 Codex。

## 10. 升级兼容

1. 每次启动重新查找已安装 AppX 版本，因此官方版本目录变化不要求重新安装。
2. 不修改 `app.asar`，Store 更新不会覆盖本方案文件。
3. 页面选择器按 Codex 版本记录并集中管理。
4. 工具栏结构变化时停止注入并留下不含敏感信息的诊断日志。
5. 官方接口字段变化时隐藏无法确认的字段，等待适配。

## 11. 验证方案

### 11.1 离线验证

1. 对所有 JavaScript 执行 Node 语法检查。
2. 确认项目没有 npm 依赖和安装后下载行为。
3. 使用同项目内的聚焦解析测试覆盖：
   - 选择 7 天窗口；
   - `100 - used_percent` 与边界限制；
   - 重置次数为 `0` 的隐藏规则；
   - 重置次数缺失不等于 `0`；
   - 从可用券中选未来最早到期日；
   - 到期日缺失；
   - 非法时间和非法百分比；
   - 不存在 7 天窗口。
4. 静态检查源代码不存在主动请求 `/wham/usage` 或 `/wham/rate-limit-reset-credits` 的逻辑。
5. 检查 CDP 地址只绑定 `127.0.0.1`。
6. 检查卸载逻辑只指向本方案明确安装目录和快捷方式。

不新增独立测试框架或无价值脚手架。

### 11.2 安装验证

1. 安装目录内容完整。
2. 新快捷方式目标正确。
3. 官方快捷方式、`WindowsApps` 和 `app.asar` 未变化。
4. 卸载脚本目标解析后仍位于明确安装目录内。

### 11.3 重启后的真实验收

由于当前 Codex 进程不是由新入口启动，必须先完成代码和离线验证，再由用户正常关闭 Codex，并从“Codex（用量显示）”启动一次。

真实验收证据：

1. 辅助程序连接到只监听回环地址的 CDP 端口。
2. 日志确认只观察到 Codex 官方响应，没有辅助程序发起的额度请求。
3. CDP 自检读取到唯一组件根标记。
4. 完整模式显示真实当前用量和重置时间。
5. 缩窄窗口后切换为缩略模式。
6. 重置次数为 `0` 时不显示任何重置相关文字。
7. 页面导航或 React 重绘后组件恢复且不重复。
8. 从原官方入口启动时 Codex 保持原样。

在完成这次重启验收前，只能声明“代码、离线验证和安装完成”，不能声明“真实 Codex 界面验收完成”。

## 12. 回退与卸载

即时回退：

1. 关闭当前 Codex。
2. 从原官方入口重新启动。

完整卸载：

1. 运行 `uninstall.ps1`。
2. 确认“Codex（用量显示）”快捷方式和 `%LOCALAPPDATA%\CodexUsageToolbar` 已删除。

不需要修复、重装或重新签名官方 Codex。

## 13. 已知限制

1. 只有从“Codex（用量显示）”入口启动时才会展示组件。
2. 严格遵守“不额外请求”后，最近到期日可能要等 Codex 自己打开相关官方界面并请求重置券明细后才出现。
3. Codex 官方页面工具栏结构大改时，组件可能暂时不显示，但 Codex 本身不受影响。
4. 当前方案依赖本机 Node.js 24；若未来卸载 Node.js，需要改为独立打包的本地可执行文件。

## 14. 验收标准

以下条件全部满足才算实施完成：

1. 用户只需点击一次新增入口，辅助程序与官方 Codex 自动启动。
2. 顶部页面工具栏显示确认过的完整或缩略文案。
3. 百分比表示每周剩余用量。
4. 剩余重置次数为 `0` 时隐藏全部重置相关内容。
5. 未观察到到期日时不虚构日期。
6. 辅助程序不创建额度请求或独立额度刷新定时器。
7. CDP 只绑定回环地址，原始响应与身份信息不落盘。
8. 官方 Codex 文件和原入口保持不变。
9. 注入失败不影响 Codex 正常工作。
10. 完成重启后的真实界面验收。
